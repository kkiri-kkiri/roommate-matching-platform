# 과거 생활 설문 컬럼 정리 — 수동 적용 전용

현재 Entity/API에는 `bug_handling`, `hair_dryer_use`가 없다. API 필드를 복원하지 않는다.
기본 DB에는 두 컬럼이 VARCHAR(30) NOT NULL, 기본값 없음으로 남아 있어 신규 JPA INSERT를 방해한다.
2026-11-01 읽기 전용 조사에서 30개 행, 6가지 값 조합을 확인했다. 각 조합은 5개 행이다.
현재 소스에서 두 컬럼에 대한 저장 의존성은 없고, 인덱스/FK/생성 컬럼/뷰/트리거/루틴/CHECK 의존성도 없었다.
Git 이력 `4b14123`에서 과거 DTO/Entity/Service 입력이 제거된 것을 확인했다.
이 사실은 향후 적용 직전에 다시 확인해야 한다.

`20261101_profile_survey_legacy_columns.sql`은 자동 실행하지 않는다. 기본 DB 적용은 별도 검토 후에만 한다.
우선 동일 MySQL 버전의 격리 복제본에서 실행한다. `@kkiri_legacy_survey_approval`이 없으면 거절한다.
프로시저 생성 자체도 DDL이므로 승인 없는 환경에서 파일을 시험 실행하지 않는다.

1. 쓰기 인스턴스·일정 수집을 중지하고 전체 DB 백업 및 복원 가능성을 확인한다.
2. 대상 DB와 물리 컬럼 정의, 외부 도구/구버전 서버의 의존성까지 확인한다.
3. 같은 세션에서 승인 변수를 설정하고 SQL을 stop-on-error로 실행한다. `--force`를 쓰지 않는다.
4. 기존 30행의 PK·사용자 ID·두 값을 별도 `profile_survey_legacy_20261101`에 보존하고 행별 비교 후 컬럼을 제거한다.
   보관 테이블은 삭제하지 않고, 사용자 삭제를 방해하는 FK도 만들지 않는다.
5. 기존 다른 컬럼·설문 옵션·참조의 무변경, JPA 신규 설문 저장, 서버 validate 시작을 확인한다.

MySQL DDL은 암묵적으로 커밋된다. 전체 단계가 한 트랜잭션으로 롤백되지는 않는다.
실패하면 보관 테이블/프로시저를 임의 삭제하고 재시도하지 않는다. 실패 단계와 보관 행을 확인한다.
적용 직후 문제가 있으면 쓰기를 계속 중지하고 검증된 전체 백업에서 복원하는 절차를 검토한다.
신규 회원에게 과거 필수 컬럼 값을 임의로 만들어 넣는 역마이그레이션은 제공하지 않는다.

2026-11-01 기본 DB 복제 병합 리허설에서 원본 30행 보관을 검증했고, 적용 전 dump를
별도 restore DB로 복원해 두 컬럼·값·전체 행·인덱스·FK와 참조 규칙까지 원본과 같음을 확인했다.
병합 후 백업 복원 및 별도 SQL 패치 재생 결과와 실제 기본 DB 수동 적용 순서는
[DEMO_MERGE_VALIDATION.md](../DEMO_MERGE_VALIDATION.md)를 따른다. 기본 DB에는 아직 적용하지 않았다.

위 내용은 리허설 당시 기록이다. 이후 사용자 승인 후 개인 기본 DB의 보관·제거와 전체 검증을 완료했다.
[실제 적용 결과/백업/복구](../DEMO_LOCAL_APPLY_20261101.md)를 따른다. 공용/운영 자동 적용은 하지 않는다.
