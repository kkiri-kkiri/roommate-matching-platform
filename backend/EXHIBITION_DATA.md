# 전시회 시연 데이터 도구

닉네임·게시글·댓글·메시지의 기존 ID를 보존하는 후속 갱신은
[EXHIBITION_TEXT_REFRESH.md](EXHIBITION_TEXT_REFRESH.md)의 `TextPreview` / `TextApply`를 사용한다.
아래의 채팅 추가 전용 제한은 일반 생성 모드에 적용된다. 텍스트 갱신 모드는 전체 출처 지문 검증을 유지한다.

2026-10-31 후속: 기존 DB를 보존한 별도 로컬 DB에 실제 적용하고 API/브라우저를 검증했다.
현재 연결·실제 건수·시연 로그인·시작/중지·백업/복구 명령은 [EXHIBITION_LOCAL_RUN.md](EXHIBITION_LOCAL_RUN.md)를 따른다.
아래의 '구현·H2 테스트 과정'과 MySQL 미실행 설명은 최초 구현 단계의 검증 범위다.

이 문서는 **향후 적용 절차**다. 구현·H2 테스트 과정에서는 MySQL에 연결하거나 Docker를 변경하지 않는다.
일반 서버 시작, `APP_SEED_MODE=CREATE/DELETE`, HTTP API로 이 도구를 실행하지 않는다.

## 구성과 수정 위치

- `src/exhibition/java/exhibition/ExhibitionCatalog.java`: 모든 가상 인물·설문·선호·게시글·댓글·대화·일정 내용.
- `ExhibitionPlanner.java`: 출처·참조·중복·수동 변경 확인, 읽기 전용 계획과 검토 토큰.
- `ExhibitionWriter.java`: 기존 업무 서비스 호출, 신규 레코드의 시연 시각, 시드끼리의 매칭 계산.
- `ExhibitionJournal.java`: 고정 시나리오 키 → DB ID·소유자·내용 지문·댓글 ID. DB와 기준일에 귀속되는 로컬 출처 파일.
- `ExhibitionTool.java`, `ExhibitionConfiguration.java`: 명시적 CLI, 최소 Spring 컨텍스트, 실행 환경 보호.
- `src/main/java/com/kkirikkiri/global/init/CommunitySeedDataService.java`: 기존 80개 시드의 정확한 제목·본문 서명만 읽기 전용 제공.
- `src/main/java/com/kkirikkiri/chat/service/ChatService.java`: 기존 검증을 공유하는 신규 생성 전용 메서드.
  동시 요청으로 생긴 기존 방도 채택하지 않으며 일반 HTTP create-or-get 동작은 유지한다.

별도 `exhibition` source set이므로 전시회 도구·새 카탈로그는 `bootJar`에 포함되지 않는다.
일반 Controller/DTO/Entity, 가입·인증·익명성·매칭 정책과 DB 스키마는 변경하지 않는다.
`DevDataInitializer`, 기존 `SeedDataService`의 자동 실행 동작도 변경하지 않는다.
후속 시연 준비에서는 `app.seed.new-user-password`(`APP_SEED_NEW_USER_PASSWORD`) 옵션을 추가했다.
local의 **신규** 시드 계정 생성 시에만 실제 가입 비밀번호 제약을 검증해 사용한다.
미지정 시 기존 UUID 방식이며, 이미 존재하는 계정의 비밀번호는 변경하지 않는다.
전시회 도구는 해당 초기화 빈, SQL 초기화, 스케줄러, 크롤러, 매칭 비동기 listener를 등록하지 않는다.
`.env`, 기본/local 설정 파일을 가져오지 않으며 DDL은 `validate`, SQL 초기화는 `never`다.

## 준비된 데이터와 예상 건수

모든 대상이 존재하지 않거나 안전하게 재사용 가능한 경우의 최대 시나리오다.
실제 적용 범위는 반드시 대상 DB의 `preview`로 확인한다. 미확인 계정·관계는 SKIP으로 줄어든다.

| 데이터 | 시나리오 |
| --- | --- |
| 일반 회원·프로필 | 기존 `seed_user01~30@hknu.ac.kr`의 ID·이메일 유지, 없으면 최대 30명 생성 |
| 프로필 | 닉네임 30개, 4개 생활관, 6개 학부/전공 조합, 다양한 학년·MBTI |

| 게시글 | 자유·나눔·택배·민원 각 20개, 최대 80개 갱신/생성 |

사진·전화번호·호실·실존 인물 이름을 사용하지 않는다. 이미 존재하는 계정의 사진 URL은 바꾸지 않는다.
원래 시드 출처만 있는 계정에 사진 URL이 있으면 별도 확인이 필요하므로 자동 채택하지 않고 SKIP한다.
프로필 이미지는 기존 전공 캐릭터 또는 기본 아바타를 사용한다. 지정 이메일로 메일을 보내지 않는다.

아침형·야행성, 비흡연·흡연, 청소·교류·공유 성향이 다른 그룹을 둔다.
잘 맞는 조합과 낮은 점수의 조합을 기존 계산기로 산출하며 고정 점수를 INSERT하지 않는다.
`refreshIncoming`/전체 `refreshOutgoing`은 호출하지 않는다. 도구가 실제 회원과 연결된 매칭 행을 갱신하지 않는다.

## 재사용·갱신·멱등성

1. 기존 계정은 원래 `SeedUserManifest`가 ID·이메일·저장 자격증명 지문을 확인하는 경우만 재사용한다.
   이메일·닉네임 패턴만 보고 출처 파일을 만들거나 기존 계정을 채택하지 않는다.
2. 처음 이관하는 글은 확인된 시드 작성자, 게시판, **기존 원문 전체**가 정확히 일치하고 후보가 하나여야 한다.
   댓글·좋아요·이미지·신고·출처 채팅·익명 매핑이 있는 기존 글은 보존하고 SKIP한다.
   해당 작성자·게시판에 수정되거나 불명확한 글이 있으면 새 글도 추가하지 않는다.
3. 이관 후에는 `post/게시판/번호` 등 고정 키와 보관된 ID로 갱신한다. 제목 변경은 새 글 생성 기준이 아니다.
4. 출처 파일의 현재 내용 지문과 DB 상태가 다르면 수동 편집·추가 참여로 보고 SKIP한다.
   건너뛴 상태를 새로운 정상 지문으로 덮어쓰지 않는다. 연관 참여자가 SKIP이면 해당 시나리오도 SKIP한다.
5. 같은 카탈로그·기준일로 재실행하면 KEEP이며 DB 쓰기를 수행하지 않는다.
   시연 중 추가된 메시지나 읽음 상태 변경도 보존한다. 기존 미확인 채팅방에 메시지를 덧붙이지 않는다.
6. 채팅·카테고리·신고는 추가 전용 시나리오다. 내용을 바꾸려면 별도 검토할 새 시나리오가 필요하며
   기존 대화를 지우거나 새 대화로 교체하지 않는다. 소유 개인 일정은 기존 서비스로 갱신할 수 있다.

기존 사용자·프로필·설문 부모·선호 부모·게시글·댓글 ID는 갱신 시 유지한다.
설문 선택지·선호 선택지·중요도 자식 행은 **기존 서비스의 전체 교체 방식**을 따른다.
이 자식 행의 ID는 갱신 시 재발급될 수 있다. 변화가 없으면 해당 서비스도 호출하지 않는다.
글의 익명 여부와 기존 작성 시각은 보존한다. 신규 글·댓글·대화만 관계 순서를 지키며 시각을 분산한다.
신규 회원의 가입 시각보다 게시글·대화가 앞서지 않도록 구성한다.

## 안전하게 자동 변경하지 않는 항목

- 기존 회원의 성별·출생연도·입학연도는 현재 수정 서비스의 대상이 아니므로 유지한다.
  신규 일반 회원은 남녀 각각 15명 구성이지만 기존 30명이 모두 남성이면 기존 성별은 그대로다.
  기존 성별을 다양화하기 위해 SQL·reflection으로 계정 수정 정책을 우회하지 않는다.
- 실제 가입과 동일하게 활성 생활관·학부·전공의 소속, 닉네임 중복, DTO 제약을 검사한다.
  코드에 없는 성별별 생활관 배정 규칙을 임의로 만들지 않는다.
- 출처가 없거나 자격증명 지문이 달라진 레거시 시드는 보존한다. 기본 개발 일반회원·관리자를 자동 채택하지 않는다.
- 기존 비밀번호·이메일·역할·상태·사진을 변경하지 않는다. 기존 계정 시연 로그인에는 기존 자격증명이 필요하다.
- 실제 수집 학교 일정, 실제 신고, 실제 이용자 제재를 변경하지 않는다. 선택 신고 처리는 COMPLETE/REJECT만 사용한다.
- 신규 시드 비밀번호는 기본적으로 임의 생성하며 출력하지 않는다. `EXHIBITION_NEW_USER_PASSWORD`를 명시하면
  **신규 생성 계정에만** 그 값을 사용한다. 기존 회원의 비밀번호 초기화 기능은 없다.
- 신규 회원은 기존 개발 시드와 같은 User/UserProfile 생성 경로를 쓴다. 가입 DTO와 활성 기준정보 제약을
  검사하지만 실제 SMTP 인증을 수행하거나 외부 학생에게 인증 메일을 보내지 않는다.
- 일반 API의 회원·게시글 조회 범위를 시연 회원만으로 필터링하지 않는다. 실제 데이터가 혼재된 DB라면
  그 데이터가 기존 API에 계속 조회될 수 있다. 공개 시연에는 실제 데이터가 없는 대상 DB인지 별도 확인한다.

## 적용 전 백업과 확인

1. 작업자가 대상 서버 UUID·schema·MySQL 버전·테이블 대소문자·마이그레이션 적용 상태를 확인한다.
   운영 환경에서는 실행하지 않는다. 실제 데이터가 혼재된 개발 DB라면 출처 불명 SKIP을 정상 결과로 받아들인다.
2. 모든 서비스 인스턴스와 개발 시드 실행을 중지한 정비 시간에 작업한다. 도구 간에는 파일 잠금과
   DB의 `GET_LOCK`을 사용하지만 일반 애플리케이션의 접속을 차단하는 유지보수 기능은 아니다.
3. 운영자가 `mysqldump` 등의 검증된 수단으로 대상 DB의 일관된 백업을 만든다.
   InnoDB라면 `--single-transaction`, 필요 시 `--routines --triggers --events`, 출력은 `--result-file`을 사용한다.
   비밀번호는 명령줄·Git·보고서에 기록하지 않는다. 백업을 별도 격리 DB에서 복원할 수 있는지 확인한다.
4. 같은 시점의 원래 `seed-users.properties`, `exhibition.json`과 경로·파일 해시를 함께 보관한다.
   아직 없는 출처 파일은 '미존재' 상태까지 기록한다. 파일은 DB 간에 복사하여 출처를 부여하는 수단이 아니다.
5. 기존 매칭·글·댓글·채팅·일정·신고의 건수와 필요한 업무 투영을 읽기 전용으로 기록한다.
   전체 DB와 해당 출처 파일은 함께 복구하는 단위다.

## 빌드와 읽기 전용 미리보기

아래는 운영자가 추후 별도로 실행할 명령이다. `backend` 디렉터리에서 실행한다.

```powershell
.\gradlew.bat prepareExhibition
$exhibitionClasspath = Get-Content -Raw build/exhibition/classpath.txt
```

`prepareExhibition`은 컴파일과 classpath 파일 작성만 한다. DB에 연결하지 않는다.
연결 정보는 기존 `.env`와 구분된 프로세스 환경변수로 공급한다.

| 환경변수 | 값·의미 |
| --- | --- |
| `SPRING_PROFILES_ACTIVE` | 정확히 `local`. prod/test/혼합/기본 프로필 거절 |
| `EXHIBITION_ENVIRONMENT` | 정확히 `local-exhibition` |
| `APP_SEED_MODE` | `NONE` 또는 미지정. CREATE/DELETE 거절 |
| `EXHIBITION_DB_SCHEMA` | 작업자가 확인한 정확한 schema 이름 |
| `EXHIBITION_DB_URL` | `jdbc:mysql://127.0.0.1:포트/schema` 또는 localhost. 임의 URL 옵션·원격 호스트 거절 |
| `EXHIBITION_DB_USERNAME` / `EXHIBITION_DB_PASSWORD` | 해당 DB의 전용 자격증명. 미리보기는 SELECT 전용 계정 권장 |
| `EXHIBITION_NEW_USER_PASSWORD` | 선택. 신규 계정에만 사용, 실제 가입 비밀번호 제약 준수 |

로컬 MySQL 인증에 필요하면 URL 옵션은 `useSSL=false&allowPublicKeyRetrieval=true` 조합만 허용한다.
추가 프로필·`SPRING_APPLICATION_JSON`은 허용하지 않는다. JVM에 prod/test 프로필이 명시돼 있어도 중단한다.
기존 DB 스키마가 없거나 다르면 validate에서 실패하며 자동 생성·마이그레이션으로 우회하지 않는다.

```powershell
java -cp $exhibitionClasspath exhibition.ExhibitionTool preview --anchor=2026-10-30
```

선택 신고 사례를 포함하려면 `--reports`를 추가한다.
기준일은 시연할 날짜에 맞춰 명시하며 동일 데이터셋의 재실행에서는 유지한다.
기본 출처 파일은 현재 작업 디렉터리 기준 `local-data/exhibition.json`, 원래 시드 출처는
`local-data/seed-users.properties`다. 필요하면 `--journal=...`, `--legacy-manifest=...`를 명시한다.

미리보기는 DB에서 SELECT만 수행한다. 사용자·게시글의 대상 ID와 소유자, CREATE/UPDATE/KEEP/SKIP 건수,
선택지 교체·댓글·좋아요·메시지 영향 건수, SKIP 이유, 최대 매칭 범위와 SHA-256 검토 토큰을 출력한다.
현재 회원정보나 자격증명 원문은 출력하지 않는다. 로컬 디렉터리·빈 잠금 파일은 생길 수 있으나
출처 JSON과 DB 데이터는 쓰지 않는다.

## 검토한 계획 적용

백업·정비 중지·미리보기 검토를 마친 뒤에만 작업자가 별도로 실행한다.
추가 프로세스 환경변수 `EXHIBITION_WRITES=ALLOW_REVIEWED_PLAN`, `EXHIBITION_OFFLINE=CONFIRMED`가 필요하다.
미리보기와 같은 대상·기준일·신고 옵션·출처 경로를 사용한다.

```powershell
java -cp $exhibitionClasspath exhibition.ExhibitionTool apply --anchor=2026-10-30 --expect=검토한64자리토큰
```

예시의 `검토한64자리토큰`은 실제 미리보기 토큰으로 대체한다. 대상 상태가 달라졌으면 적용하지 않는다.
사용자 → 게시글 → 댓글 순서의 잠금 후 핵심 쓰기 직전에도 계획을 재검증한다.
조회·기존 업무 서비스·시드끼리 매칭 이외의 임의 SQL 초기화는 없다.
날짜 조정 SQL은 방금 생성한 시연 레코드에만 사용한다. 읽음 확인은 ChatService.markRead로 처리한다.
방 생성은 ChatService.createNewRoom으로 수행하여 사전 조회와 생성 사이의 UNIQUE 경합에서도 기존 방을 채택하지 않는다.

완료 후 같은 조건으로 preview하여 KEEP/SKIP만 남는지 확인한다.
선택한 실제 API와 프론트에서 프로필·설문·추천·익명 댓글·채팅·읽음·개인 일정·관리자 신고를 확인한다.
도구 실행 후 일반 서버를 재개할 때에도 `APP_SEED_MODE=NONE`을 유지해야 한다.
기존 CREATE를 다시 사용하면 과거 `[SEED]` 제목의 글을 새로 추가할 수 있다.

## 실패·중단 시 복구

적용 전 출처 파일에 APPLYING을 먼저 기록한다. 핵심 회원/설문/커뮤니티/일정은 한 트랜잭션이다.
채팅방 생성과 매칭은 기존 서비스의 독립 트랜잭션을 따르므로 **전체 실행이 단일 DB 트랜잭션은 아니다**.
채팅방만 생성되고 메시지 단계에서 실패하는 등 일부 커밋이 가능하다.

완료 출처 파일 기록 전 실패·프로세스 종료·파일 저장 오류가 나면 APPLYING이 남는다.
이 경우 도구는 다음 실행을 거절한다. 임의 재실행·출처 파일 삭제·이메일로 재채택하지 않는다.
`APP_SEED_MODE=DELETE`, FK 검사 해제, 전체 테이블 정리로 복구하지 않는다.

1. 서비스를 중지 상태로 유지하고 예외 분류와 적용 전 백업을 확인한다.
2. 적용 후 실제 사용자가 기록을 남기지 않은 정비 시간이었다면, 운영자가 검증한 절차로
   **적용 전 DB 전체와 당시 출처 파일 둘을 같은 시점으로 복원**한다. 처음 없던 파일은 당시 미존재 상태로 복구한다.
3. 적용 후 실제 이용 기록이 있다면 전체 복원은 그 기록을 잃을 수 있다. 자동 복구하지 말고
   DBA가 변경분·추가 기록·FK를 대조한 별도의 복구안을 작성한다.
4. 복구 후 읽기 전용 점검과 새 preview를 수행한다. 예전 검토 토큰을 재사용하지 않는다.

파일 지문은 내부 출처와 변경 감지 수단이다. 수동 편집으로 출처를 조작하거나 복사하지 않는다.
일반 데이터셋 수정은 Catalog에서 하고 preview를 다시 검토한다. 시드 출처 파일은 Git에 포함하지 않는다.

## 검증 범위

최종 실행 결과와 변경 파일 목록은 [EXHIBITION_VALIDATION.md](EXHIBITION_VALIDATION.md)에 기록한다.

`src/test/java/exhibition/`에서 실제 서비스·Repository·DTO를 H2 메모리 DB로 검증한다.
미리보기 무변경, 반복 실행의 전체 데이터 동일성, 기존 ID/자격증명/성별 보존, 불명 계정·수동 편집·실제 댓글 보존,
기존 대화·학교 일정 보존, 익명 번호·비노출, 매칭 고저점, 읽음/미읽음, 신고 완료/반려, 롤백·중단 차단을 검사한다.

H2는 MySQL 테이블 대소문자·collation·잠금·GET_LOCK·물리 DDL·실행계획을 대신하지 않는다.
실제 MySQL 적용, Docker, 실제 브라우저 E2E, 학교 크롤링·SMTP·AI 호출은 이 작업에서 수행하지 않는다.
