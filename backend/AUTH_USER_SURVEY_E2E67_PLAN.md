## 재사용과 실행 순서

`npm run test:e2e -- --aus-p0`를 이번 전체 실행에 사용한다. 프로젝트 의존성으로 기존 login
기준선을 먼저 실행하고 성공한 경우에만 독립 P0 8개를 실행한다. 기존 test.step을 단독 선택하지 않는다.
기존 user-workflow의 가입/설문 동작은 `lib/aus-flows.cjs`로 이동해 양쪽이 공유한다.
auth-boundaries가 사용하는 `lib/flows.cjs`의 로그인/로그아웃/제어를 재사용한다.
기존 auth-boundaries의 타 도메인·STOMP 검증은 실행하지 않는다.

실패만 재검증할 때는 `npm run test:e2e -- --aus-p0-recheck <원본 실행 ID>`를 사용한다.
원본 results.json의 SHA-256과 실패 ID를 기록하고, 새 자원 생성 전에 `--list`로 선택 수를 확인한다.
이미 PASS한 로그인 기준선과 다른 P0는 `--no-deps`로 반복하지 않는다.

P0 9개는 각각 자체 fixture로 독립 실행한다. B9 안의 A/B 전환만 의도적으로 동일 컨텍스트다.
P0 검토 후 중단한다. P1은 이후 승인 시 B10→B11→B12→B13→B14→B15 순서로 실행할 계획이며,
각 사례의 내부 입력 조합은 별도로 기록한다. B3의 가입 토큰 만료와 B10의 인증번호 만료는 다르다.

## 테스트 전용 보완

- E2eServer 메모리 메일에서 인증번호·재설정 토큰을 종류별 수집·한 번 꺼내기 한다.
  서버→소유 Node 비공개 pipe→인증된 loopback 제어→테스트 메모리로 전달하며 로그/근거에 원문을 남기지 않는다.
- E2E 전용 가입 토큰 TTL 8/300초, 기존 JWT TTL 8/3600초만 허용한다.
  재전송 cooldown 60초 및 MySQL 공유 limiter는 유지한다. 운영 속성 파일은 수정하지 않는다.
- 새 격리 DB에 화면과 일치하는 컴퓨터응용수학부/법경영학부 및 소속 전공 3개를 추가한다.
  기존 HK자율전공학부와 계정 A/B/관리자 fixture를 유지한다.
- JDBC는 계정/학적/MBTI, 프로필 설문·선택지, 선호·선택지·가중치,
  재설정 토큰의 사용 여부만 읽는다. 자격증명·인증 토큰/코드/해시는 조회하지 않는다.
- 브라우저 근거는 HTTP method/path/status, 선택된 비밀 없는 관찰만 보존한다.
  E2E 전용 서버 filter는 API method/path/status를 별도 기록한다. OPTIONS는 애플리케이션 HTTP 수에서 제외한다.
  trace/screenshot/video는 실패 시에도 끈다.

## 자원·정리

로컬 Docker Linux 엔진과 기존 이미지/Chromium 실행 파일 존재를 먼저 확인한다.
이미지 `mysql:8.0.46-oraclelinux9`의 기존 ID를 기록하고 `--pull=never`로만 생성한다.
이름 `kkiri-e2e-<12 hex>`, DB `kkiri_e2e_<id>`, 전용 계정 `e2e_<id>`만 사용한다.
생성 직전에 정확한 새 이름과 이미지 ID를 출력한다. 이름/포트 충돌 시 기존 대상을 재사용하거나 종료하지 않는다.
React 127.0.0.1:13000, Spring 18080, MySQL 13316; MySQL data는 tmpfs, named volume 없음.
서버는 e2e 프로필·DDL validate·SQL never·seed NONE·스케줄/실제 SMTP/AI/학교 통신 비활성이다.
새 빈 스키마만 별도 prepare로 Entity DDL을 만든다.

정상 전체 P0 1회는 새 컨테이너 1개를 생성·정리한다. 실패 후 수정 재검증은 필요한 실패/영향 사례만
새 소유 컨테이너에서 수행하고 실행별 이름·근거를 별도로 남긴다. 추가 전체 suite는 실행하지 않는다.
테스트 fixture DELETE와 컨테이너 삭제는 해당 신규 소유 UUID/이름/권한/라벨 확인 범위다.
기존 보존 자원에는 내부 inspect/DB 접속을 하지 않는다.
공용 `test:e2e:clean`은 기존 보존 산출물을 건드릴 수 있어 이번에 호출하지 않는다.

## 근거 및 결과 작성

`backend/build/full-service-e2e/<id>/`에 source-before/after, preflight, run,
results, browser, database, server-http, 마스킹된 진단을 보존한다.
최초 실패를 수정·삭제하거나 PASS로 덮어쓰지 않는다. 후속 실행은 새 ID다.
논리 사례 최종 상태와 실행 시도 수, 실제 브라우저 HTTP와 서버 관찰을 구분한다.
화면의 자동 조회가 타 도메인을 호출하더라도 그 도메인의 사례 PASS로 집계하지 않는다.
서비스/API/스키마 결함, 프론트 결함, 실행기/fixture 오류, 미확정 정책을 구분한다.

P1 실행 전에는 여섯 사례의 세부 입력별 matrix, 테스트 메일 만료 경로, 실패/지연 주입과 복구,
다중 탭 관찰 및 비밀 비노출을 준비하고 별도 실행 승인을 받는다.
